# v0.3.3 — Maneuver IHM English mode (FR/EN), systematic bilingual spec

A minor release on top of `0.3.1.post1` (no breaking API changes; the analysis
pipeline is untouched). It makes the maneuver IHM **bilingual French/English**
for international users — a fixed **FR | EN switcher at the top-right** toggles
the whole presentation/interaction language instantly — and turns bilingual
support into a **systematic specification** enforced in CI for every future IHM
evolution.

## Highlights

- **FR | EN language switcher, top-right, in every mode.** `#langSwitch` is a
  fixed-position toggle visible in the topology view, the exploration map and
  the modals. The choice persists in `localStorage["manoeuvre_lang"]`
  (French remains the default) and switching is instant — no page reload, no
  loss of working state (loaded substation, edited target, computed sequence).

- **Front-only i18n layer** in `scripts/manoeuvre_ihm_assets/index.html`:
  - exact dictionary `I18N_EN` (~370 entries: static texts, tooltips
    `title=`, `placeholder=`, `<option>` labels, JS message templates with
    `{placeholders}`);
  - pattern rules `I18N_PATTERNS` for parameterised server/module strings —
    manoeuvre `raison` labels (`ré-aiguillage '<feeder>' vers <busbar>` →
    `busbar transfer of '…' to …`), `targets.py` / `verification.py` messages,
    detailed discrepancies, R10ter good-practice alerts, endpoint errors, and
    the v0.3.2 named diagnostics of `/api/nodale_to_detaillee` (equipment to
    reconnect / not grouped as intended / impossible to isolate);
  - helpers `t()` / `tp()`, `translateDom()` DOM walk (text nodes +
    `title`/`placeholder` attributes, SVG subtrees excluded), an
    `html[lang="en"]` override for the CSS-injected "topologie cible
    atteinte" text, and bilingual switching-device abbreviations
    (DJ/SA/INT ↔ CB/DS/LBS);
  - consistent power-system terminology (poste → substation, sectionneur →
    disconnector, jeu de barres → busbar, ré-aiguillage → busbar transfer,
    manœuvre → switching operation…).

- **French stays canonical.** Markup, server data and saved files are
  unchanged: a scenario or sequence saved in EN mode is **byte-identical** to
  its FR version; the `/manuelle/` raison detection and the goldens are
  untouched. Translation happens at display time only.

- **Systematic specification** (`docs/manoeuvre/ihm.md` new **§ 2bis**,
  `manoeuvre/CLAUDE.md`, root `CLAUDE.md`): every new user-visible IHM string
  (element text, `title=`, `placeholder=`, `<option>`, JS-built message,
  displayed server message) must ship with its English translation — an exact
  `I18N_EN` entry, or an `I18N_PATTERNS` rule when parameterised — and JS
  strings go through `t()`/`tp()`, never a raw French literal assigned to the
  DOM. The same requirement applies to any future IHM of the project.

- **CI guard `tests/manoeuvre/test_ihm_i18n.py`** (pure text analysis — no
  Flask, no pypowsybl, always runs): switcher present and top-right fixed,
  i18n layer present (dictionary, patterns, helpers, localStorage key,
  `html[lang="en"]` rule), **every** markup `title=`/`placeholder=` attribute
  and static text node covered by `I18N_EN` (tight explicit allowlist:
  the FR/EN buttons themselves and the "RTE 7000 ⓘ" brand), and a sample of
  critical dynamic strings + pattern rules verified. Adding a UI string
  without its translation fails CI.

## Compatibility

- No public API changes; no dependency changes. The analysis pipeline
  (`run_analysis*`) is untouched — this release only changes the maneuver IHM
  front-end asset, docs and tests.
- Saved scenario/sequence JSON files are unchanged whatever the display
  language (French canonical), so existing fixtures and the shared scenario
  base are unaffected.

## Verification

- New i18n guard suite green (5 tests, pure text — runs without pypowsybl).
- Script block syntax-checked (`node --check`); translation engine
  unit-checked under node (exact entries, pattern rules, `{placeholder}`
  templates, FR round-trip identity, bilingual `kindShort`).
- Real-browser end-to-end under Playwright/Chromium: FR default → EN switch
  (headings, buttons, placeholders, `<option>` labels, `document.title`,
  `html[lang]`) → reload persistence via localStorage → back to FR, with no
  JavaScript errors beyond the expected fetch failures of the API-less static
  harness.
- Existing structure guards of `test_ihm_frontend_asset.py` verified intact
  (required/forbidden markers, single `<script>` block, balanced braces —
  French markers stay present since French markup remains canonical).
